## 1. Роль компаньона сейчас

Компаньон — независимый read-only инженерный помощник. Он должен сохранять контекст проекта, проверять доказательства, помогать планировать проверки и находить пробелы в данных. Он не должен заново придумывать уже согласованное решение, выдавать общие гипотезы за диагностику или заявлять, что проверил исходный код, которого нет в его рабочем репозитории.

Текущая задача Pleer1 — валидация исправления отдельного YouTube-поиска и подготовка безопасной проверки на физическом iPhone. Повторные симуляции не запускать: пользователь прямо попросил прекратить повторные запуски симулятора. Допускается macOS command-line harness и сборка generic iOS device без симулятора. Не менять UI до проверки ключевого поведения на устройстве.

## 4. Поиск: согласованное ожидаемое поведение

- Обычный запрос (например, `Concrete`) должен находить отдельные видео-треки, а не только плейлисты или Mix.
- Явный запрос коллекции (например, `crystal castles playlist`) должен находить коллекции.
- Тип результата определяется структурой renderer/типизированными данными и ID, а не словами в заголовке.
- Проверять цепочку отдельно: HTTP → renderer-кандидаты → parser → фильтры → итоговый список UI → выбранный пользователем объект.
- Весь анализ одного поиска коррелировать по одному `searchID`.

## 7. Обязательный формат краткого статуса

- **Подтверждено:** только факты с источником.

## 8. Актуальный статус на 2026-11-18 — parser fix подтверждён harness, Lab ещё не обновлён

### Подтверждённая причина

В коде Build #14 (`Pleer1` commit `14956c5fbe07d39af97f73d4b462efc3fb42e66f`) оба parser-пути добавляли video ID в `seen`, а затем повторно фильтровали общий массив `videos + playlists + radios` тем же `seen`. В результате отдельные видео отбрасывались повторной дедупликацией, а коллекции могли оставаться. Это подтверждённый дефект реализации, а не догадка по логам.

### Исправление и проверка

Изменения внесены только в публичную временную ветку `Pleer1-temporary/verify/youtube-search-macos-2026-11-18`, не в Main и не в Lab:

- `plei/Sources/YouTubeHTMLSearch.swift`: аналогичное исправление HTML fallback; commit `01fb4d6e1a00dcc27ec77ad3860f4755f3d1746c`.
- Разделение ordinary video search и explicit playlist/Mix intent; normalization не должна удалять диакритические знаки кириллицы.
- No-simulator harness компилирует реальные production parser source files, а не переписанную копию логики.
