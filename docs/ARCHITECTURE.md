# Архитектура облачного ИИ-компаньона

## Цель

Создать отдельного облачного инженерного помощника с диалоговым вводом задач, доступом к контексту лабораторного репозитория и постепенно расширяемыми полномочиями. Независимое ревью должно дополнять, а не заменять компаньона.

## 1. OpenCode — основной coding agent

OpenCode запускается в GitHub Actions в headless-режиме через `opencode run`.

Первый рабочий контур:
- запуск workflow в GitHub Actions;
- пользователь передаёт вопрос через input workflow;
- агент читает только `Pleer1-Next`;
- ответ сохраняется как artifact;
- агент не может редактировать файлы, выполнять shell-команды или обращаться к внешним веб-инструментам;
- модель и runtime существуют только в пределах временного runner.

## 2. Модель и вычисления

Для следующего этапа выбрана `qwen3:4b-instruct` через Ollama.

Причина выбора:
- в прямом тесте Instruct выполнила требование «ровно одно слово» ответом из 5 токенов;
- Thinking-модель вывела рассуждения в пользовательский текст;
- обе модели успешно сформировали структурированный вызов тестового инструмента.

Это пока не доказывает, что OpenCode корректно работает с моделью: нужен отдельный интеграционный запуск.

Модель скачивается на временную виртуальную машину GitHub, inference выполняется на этой машине, после завершения job среда уничтожается. Внешний платный LLM API и ключ модели не используются. Бесплатные лимиты и доступность GitHub Actions зависят от актуальных ограничений GitHub и настроек аккаунта.

## 3. Alibaba Open Code Review

OCR поддерживает два разных режима:
- прямой режим: OCR сам обращается к настроенному LLM endpoint; текущий `ocr-review.yml` требует credentials;
- delegation mode: OCR выбирает файлы и предоставляет review rules, а OpenCode выполняет интеллектуальную проверку своей моделью; отдельный OCR LLM endpoint может не понадобиться.

План — рассмотреть delegation mode после проверки базового OpenCode.

## 4. GitHub и границы доступа

Все эксперименты происходят исключительно в `Pleer1-Next`. Запуск агента получает только read permissions. Он не создаёт коммиты, PR, релизы и IPA и не имеет доступа к другим репозиториям.

## Этапы внедрения

1. Подготовить безопасные инструкции и read-only конфигурацию.
2. Проверить модель напрямую через Ollama.
3. Проверить качество ответов и вызовов инструментов.
4. Запустить OpenCode с Qwen3 Instruct и проверить реальный анализ репозитория.
5. Рассмотреть OCR delegation mode.
6. Только после испытаний обсуждать контролируемые правки в отдельной ветке этой лаборатории.

## Почему начинаем с read-only

Coding agents способны редактировать файлы, запускать команды и обращаться к внешним инструментам. До проверки поведения это неоправданный риск. Начинаем с чтения и анализа, расширяем полномочия только поэтапно.
