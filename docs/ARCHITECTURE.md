# Архитектура облачного ИИ-компаньона

## Цель

Создать облачного инженерного помощника с диалоговым вводом задач, доступом к контексту репозитория и постепенно расширяемыми полномочиями. Независимое ревью должно дополнять, а не заменять компаньона.

## 1. OpenCode — основной coding agent

OpenCode запускается в GitHub Actions в headless-режиме через `opencode run`.

Первый прототип:
- ручной запуск через `workflow_dispatch`;
- пользователь передаёт вопрос через input workflow;
- агент читает только `Pleer1-Next`;
- ответ сохраняется как artifact;
- агент не может редактировать файлы, выполнять shell-команды или обращаться к внешним веб-инструментам;
- модель и runtime существуют только в пределах временного runner.

## 2. Модель и вычисления

Для первого облачного эксперимента используется Ollama с `qwen3:4b`, запущенная на стандартном GitHub-hosted Ubuntu runner.

Это не локальная Ollama на компьютере пользователя и не внешний платный API:
- модель скачивается на временную виртуальную машину GitHub;
- inference выполняется CPU/RAM этой машины;
- после завершения job среда уничтожается;
- для стандартных GitHub-hosted runners в публичном репозитории GitHub указывает бесплатное и неограниченное использование.

Ограничения прототипа:
- 4B-модель слабее крупных coding-моделей;
- CPU inference может быть медленным;
- качество вызова инструментов и устойчивость OpenCode + Ollama нужно проверить реальным запуском;
- бесплатность runner не означает бесплатность любого внешнего API, но этот первый вариант внешний inference API не использует.

## 3. Alibaba Open Code Review

OCR поддерживает два разных режима:
- прямой режим: OCR сам обращается к настроенному LLM endpoint; текущий `ocr-review.yml` требует credentials;
- delegation mode: OCR выбирает файлы и предоставляет review rules, а OpenCode выполняет интеллектуальную проверку своей моделью; отдельный OCR LLM endpoint не нужен.

План — подключить delegation mode к облачному OpenCode после проверки базового прототипа.

## 4. GitHub

GitHub хранит инструкции, workflow и отчёты. Все эксперименты происходят исключительно в `Pleer1-Next`.

Запуск агента не получает write permission. Он не создаёт коммиты, PR, релизы и IPA и не имеет доступа к другим репозиториям.

## Этапы внедрения

1. Подготовить безопасные инструкции и read-only конфигурацию.
2. Запустить первый облачный smoke test с Qwen3 4B.
3. Проверить качество ответов, скорость, память и стабильность tool calls.
4. Подключить OCR delegation mode без отдельного LLM API.
5. Только после испытаний обсуждать контролируемые правки в отдельной ветке.
6. Не подключать основные репозитории без отдельного явного решения.

## Почему начинаем с read-only

Coding agents способны редактировать файлы, запускать команды и обращаться к внешним инструментам. До проверки модели и поведения это неоправданный риск. Начинаем с чтения и анализа, расширяем полномочия только поэтапно.
