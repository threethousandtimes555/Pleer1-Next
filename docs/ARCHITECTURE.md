# Архитектура ИИ-компаньона

## Цель

Собрать не просто PR-ревизор, а инженерного помощника с диалоговым интерфейсом, доступом к контексту проекта и контролируемыми инструментами. Независимое ревью должно дополнять, а не заменять компаньона.

## Предлагаемые компоненты

### 1. OpenCode — основной coding agent

Предварительный выбор: OpenCode как открытый coding agent с поддержкой разных моделей, локальных провайдеров, специализированных агентов и настраиваемых разрешений.

Его роль:
- изучать файлы и связи между модулями;
- отвечать на вопросы по архитектуре;
- объяснять ошибки и логи;
- составлять план исправления;
- предлагать патчи и тесты;
- работать с Git в рамках разрешённой рабочей копии.

До выбора модели и локального окружения это архитектурное решение, а не установленная система.

### 2. Alibaba Open Code Review — независимый ревизор

Использовать CLI `@alibaba-group/open-code-review` для отдельного анализа diff/веток. Начальный режим:
- запуск только вручную;
- только чтение кода и diff;
- отчёт сохраняется как GitHub Actions artifact;
- без публикации inline-комментариев;
- без записи в исходники;
- без доступа к другим репозиториям.

Для вызова нужен выбранный LLM provider. Секреты и переменные настраиваются владельцем репозитория отдельно. Не добавлять ключи в Git.

### 3. GitHub

GitHub хранит инструкции, историю и результаты ревью. Все эксперименты происходят в Pleer1-Next. Изменения других репозиториев не входят в полномочия этого проекта.

## Этапы внедрения

1. Подготовить безопасные инструкции и структуру — текущий этап.
2. Выбрать и настроить локальный интерфейс OpenCode.
3. Выбрать модель и оценить стоимость, качество и политику обработки данных.
4. Проверить компаньона на копии/учебном примере, не подключая рабочие репозитории.
5. Настроить ручной Open Code Review после выбора LLM provider.
6. Только после испытаний обсуждать дополнительные интеграции.

## Почему не включаем автономную работу сразу

Coding agents могут редактировать файлы, запускать команды и обращаться к внешним инструментам. До проверки поведения и настройки permissions это неоправданный риск. Начинаем с чтения и анализа, расширяем полномочия постепенно.
